# Known Risks and Remediation Priorities (updated for 1.0.0-rc.3, 2026-10-19)

Ordered by suggested priority.

1. **Refresh tokens are not rotated; no MFA.** Revocation is per user (`token_version`), not per token/device.
2. **Tokens are held in JavaScript storage** by the SPA (XSS exposure). Cookie-based sessions with CSRF protection were not introduced.
3. **Tenant isolation is application-level only.** No composite tenant foreign keys and no Postgres row-level security; a missed filter would leak. Mitigated by a cross-org sweep (5724 calls, 0 leaks) and tests.
4. **Audit is not tamper-proof.** DB administrators can alter or drop rows/triggers. The ORM guard and DB triggers stop application-level changes only. No hash chain or external shipping.
5. **Postgres audit trigger SQL not executed** in this environment.
6. **Legacy services still commit before auditing** (only user create/update were converted to flush-audit-commit), so an audit write failure there can leave a change without a record.
7. **Failed-denial auditing is best-effort.**
8. **Global model registry** (`ModelRecord`) has no organization id by design.
9. **No encryption at rest** for DB or media.
10. **Frontend dev dependency vulnerabilities** (tailwind toolchain) and 2 moderate production findings.
11. **Container/compose not scanned**; dev credentials in compose.
12. **Transitive Python dependencies not audited**; tests ran on SQLAlchemy 2.0.54 not the pinned 2.1.4.
13. **Locked accounts reveal the lock before the password check** (existing test requires it).
14. Lifecycle covers a limited set of resource types; no automated retention runs; backups not addressed.

## Phase 15 additions (MLOps / observability)
15. **Platform-level model rows are shared and not immutable.** Model rows created before Phase 15 (owner NULL) are visible to every organization and are not protected by the immutability guard; any holder of the relevant legacy permission path could still affect behaviour that reads them.
16. **Signal deduplication is service-level.** Two truly concurrent writers could create two open rows for one dedup key (no DB unique constraint, to allow recurrence episodes).
17. **Metrics are process-local** (reset on restart, not aggregated across workers) and the JSON/Prometheus endpoints are only as private as `observability:read`.
18. **Artifact verification is hash/stat only.** AEGIS never loads or executes uploaded model files; trust in a file's origin is out of scope.
19. **Approval is not deployment gating.** There is no serving environment, so "approved" does not control what runs in production.
20. **Redaction is pattern-based**; novel secret formats in free-text log messages may not be matched.
21. Postgres execution of the Phase 15 migration was not tested (SQLite only).

## Phase 16 additions (analytics / reporting)
22. **No PDF export and no AI-written summaries.** Only JSON, CSV and HTML; `ai_generated_text` is always null.
23. **Generation is synchronous.** Large windows are bounded (window, rows, artifact size) but there is no queue; a very slow query blocks a worker for its duration. 6 concurrent generations completed on SQLite in testing; heavier load is untested.
24. **Percentile and geo fetches are capped** at `ANALYTICS_MAX_ROWS` (most recent first); results are flagged partial when truncated, but are not exact beyond the cap.
25. **Report files are not encrypted at rest** and live on the API host's disk; retention is enforced on read and by the admin purge endpoint, not by a scheduler.
26. **Visibility is creator/administrator or organization.** There is no per-user sharing list; an organization report requires readers to hold the permissions it needed, but its contents were visible to the author at generation time.
27. **Geo suppression is simple k-suppression** (k=3) at fixed 0.1 degree cells; differencing across overlapping windows/filters could still reveal small counts. No differential privacy.
28. **Process-local request metrics** appear in the system section (per worker, reset on restart).
29. **Index effect not benchmarked before/after**: composite indexes are in place and migrate cleanly. Phase 17 measured absolute timings (`scripts/benchmark_queries.py`) but has no pre-index baseline, so no improvement is claimed; Postgres execution of migration `c16r3p0rt01` is untested.
30. ~~The generic 422 handler echoes the rejected input value.~~ **Fixed in Phase 17**: validation errors now return only `type`, `loc`, `msg` and `request_id`; regression tests in `test_integration_errors.py`.
31. ~~One transient `503` from `/health/ready`, cause not identified.~~ **Root cause found and fixed in Phase 18**: the storage readiness probe used one fixed file name, so concurrent probes raced (reproduced: 28 of 300 concurrent calls returned 503). Each probe now uses a unique name; regression test `tests/test_release_health.py` fails on the old code.

## Phase 17 additions (integration / reliability)
32. **Device routes returned 422 instead of 401 for missing credentials** — fixed (`require_device_auth`); regression test in `test_integration_sweeps.py`.
33. ~~(open, low) A stored out-of-range coordinate made `GET /events` return 500.~~ **Fixed (1.0.0-rc.2):** response schemas (`GeoLocationResponseFields`) return stored values as they are; requests are still range-validated. Regression test in `test_events.py`.
34. ~~(open, moderate) `react-router` 6.x advisories.~~ **Fixed in the final stabilization pass**: upgraded to `react-router-dom` 7.18.4; `npm audit --omit=dev` reports 0 vulnerabilities; type-check, build and every browser walk pass. (Original: `npm audit --omit=dev`: `react-router`/`react-router-dom` 6.x (open redirect via backslash in `<Link>`/`useNavigate`, SSR-hydration issue). The fix is a major upgrade to 7.x. The app never navigates to a user-supplied URL (grep-verified) and does not use SSR, so exposure is low; upgrade deferred as an unrelated refactor.)
35. **(open, info)** bandit (medium+): two B608 findings in `app/edge/local_store.py` build SQL from code-controlled column names with bound values (not user input); `DEFAULT_SECRET` is refused at startup in production. `pip-audit` reported no known vulnerabilities in `requirements.txt` at the time of the run. Not part of CI by default (tools are optional in `security_checks.py`).
36. **CI has never run on GitHub Actions.** The workflow was validated as YAML and every command in it was run locally; runner differences (Python/Node patch versions) are untested.
37. **All jobs are synchronous** (ingestion, inference, tracking, reports, sync): no queue, no worker, no cancellation of running work. Status values are truthful (terminal when the request returns) and finished jobs cannot be retried or cancelled.
38. **Coverage is line coverage only** and says nothing about assertion quality; no frontend unit/component tests exist.

## Phase 18 additions (release / deployment)
39. ~~(accepted, low) ORM vs. migration differences on `model_records`.~~ **Resolved in the final stabilization pass**: the ORM now declares the unique `(name, version)` index and nullable `framework_metadata`; `alembic check` reports no differences and `scripts/check_schema_drift.py` has no allow-list. The cross-organization (name, version) uniqueness note still applies: registering a pair another organization used returns 409 (names only, no content).
40. **(fixed)** `GET /sensors?measurement_type=` returned HTTP 500 on PostgreSQL (`json LIKE` is not an operator there). Fixed with a cast; regression test compiles the query for the PostgreSQL dialect. Found only because the suite was run against a real PostgreSQL 16.
41. **(fixed)** No way to create the first administrator in production (`seed.py` refuses there). Added `scripts/bootstrap_admin.py` (password from env/prompt only, refuses a second admin per organization, audited).
42. **(fixed)** The frontend had no error boundary (a render exception blanked the app) and an expired refresh token left the user on a failing page. Added `ErrorBoundary` and a session-expired event that returns to login; browser-verified (8/8).
43. ~~(open, medium) Access and refresh tokens in browser `localStorage`.~~ **Fixed (1.0.0-rc.2).** Browser sessions keep the access token in memory only; the refresh token is an `HttpOnly; SameSite=Strict; Path=/api/v1/auth` cookie (Secure in production) that page scripts cannot read, accepted by `/auth/refresh` only with the `X-Session-Mode: cookie` header (CSRF guard). Legacy `localStorage` keys are wiped. The CSP (`script-src 'self'`) remains as defence in depth. Browser-verified: cookie flags, not readable from `document.cookie`, no tokens in storage, session survives reload, revocation still signs out. Residual: a script running in the page can still use the in-memory access token while the page is open (inherent to bearer tokens in an SPA).
44. ~~(open, low) PostgreSQL-only test failures.~~ **Fixed (consolidation pass), and one was a real defect.** Reproduced on PostgreSQL 16.10: 29 failures. 26 were fabricated foreign keys in fixtures (`user-1`, `u1`, `asset-1`, ...): fixed with real rows (`referenced_rows` fixture), no assertion changed. 2 were tests assuming naive datetimes: fixed to convert properly (the investigation test is now stricter on PostgreSQL). **1 was an application defect** -- see item 54.
45. **(open, info)** Docker images and `docker-compose.yml` have never been built or run (no Docker in either verification environment); `docker compose config` validates the file. The CI `containers` job is the first real test. Base images are pinned by tag, not by digest. The consolidation pass added a CSP header check and a persistence-across-restart check to that job.
46. ~~(open, low) No orphan-file sweeper.~~ **Fixed (1.0.0-rc.2):** `scripts/sweep_orphan_files.py` lists storage files no media or report row references (report-only by default; `--delete` removes only files older than `--min-age-hours`, default 24). Tests in `test_orphan_sweep.py`; RUNBOOKS §6 updated.
47. **(partly fixed, info)** ~~`SECRET_KEY` rotation has no grace period.~~ Fixed (1.0.0-rc.2): former keys listed in `SECRET_KEY_PREVIOUS` still verify existing tokens (never sign new ones); production refuses a short former key. Still open: rate limits and metrics are per process, so running more than one backend process weakens both.
48. ~~(open, info) Dependency scanning ran once locally.~~ **Automated (1.0.0-rc.2):** CI runs pip-audit, bandit, `npm audit` and a `detect-secrets` scan on every push; `scripts/verify_release.py` runs the same locally. Latest local results: all clean (`npm audit` 0, pip-audit none, bandit medium+ none, no new secret findings).

## Final stabilization additions (Windows 11 verification pass)
49. **(fixed)** `scripts/seed.py` called `Base.metadata.create_all()`; on a database behind the migration head this created tables outside Alembic and broke the next `alembic upgrade head`. Now refuses unless at head; regression tests in `test_release_seed.py`.
50. **(fixed)** The documented minimum "Python 3.11+" was false (`numpy==2.5.4` needs 3.12) and `psycopg2-binary==2.9.10` could not install on Python 3.14. Docs now say 3.12+; pin is 2.9.11. Python 3.12 itself was not tested locally (3.14 was; CI targets 3.13).
51. ~~(open, low, development only) Tailwind CSS 3 toolchain advisories.~~ **Fixed (1.0.0-rc.2):** migrated to Tailwind CSS 4 with the official upgrade tool; full `npm audit` reports 0 vulnerabilities. Visual equivalence checked by pixel-diffing 17 screenshots.
52. ~~(open, info) Two slowapi Limiter instances.~~ **Fixed (1.0.0-rc.2):** one shared limiter (`app/core/rate_limit.py`). `/auth/refresh` has its own `RATE_LIMIT_REFRESH` (120/min) because browsers call it on every full page load; login and password change keep `RATE_LIMIT_AUTH` (10/min).
53. **(open, info)** Browser verification covers rendering and API errors on every route for all four roles and at 390 px width, plus the reporting and session/error-boundary journeys; it does not click through every form. Frontend unit/component tests now exist (Vitest + Testing Library, 49 tests: navigation, origin badge, admin guard, error boundary, API error handling, CSP rendering, version labels); most page components are still covered only by the browser walk.

## Consolidation pass additions (2026-10-18)
54. **(fixed, medium -- data correctness)** On PostgreSQL servers whose `TimeZone` is not UTC (the default for a self-installed server: initdb copies the OS zone), analytics dashboards and reports labelled hourly/daily buckets in the server's local time instead of UTC, and events late in the window's last day were **silently dropped** from bucketed series (reproduced: 6 of 7 events shown, every bucket shifted by +05:30). Cause: `to_char()` formats `timestamptz` in the session zone. Fix: `to_char(timezone('UTC', col), ...)` in `analytics_service.bucket_expr`. Regression tests: a dialect-compiled check (runs everywhere) and a real-session check with `SET TIME ZONE 'Pacific/Chatham'` (runs on PostgreSQL); both fail on the old code. Totals and window filtering were already correct. UTC-only CI and the earlier UTC sandbox could not have shown this.
55. ~~(open, licensing) `react-leaflet` under the Hippocratic License 2.1.~~ **Resolved (1.0.0-rc.2):** replaced by a small wrapper over plain Leaflet (BSD-2-Clause); the shipped frontend now contains only MIT and BSD-2 code. The project is MIT-licensed.
56. **(open, info -- outside the repository)** A local, truncated archive from an aborted backup job on the development machine contains a copy of a development `backend/.env` (only the public placeholder secret). It is not tracked by git and must not be shared; the owner has the details.
57. **(fixed)** The main JavaScript bundle was 930 kB (one chunk). Pages are now code-split with `React.lazy` (main chunk 337 kB, 100 kB gzipped); every route still renders in the browser walk.
58. **(fixed)** CI ran only on pushes to `main` and on pull requests, so pushing the release branch would not have triggered it; it now also runs on `release/**` and on demand, and tests Python 3.12, 3.13 and 3.14.

## Release candidate 2 additions (2026-10-19)
59. **(fixed, medium -- data correctness)** On SQLite (the default local database) every timestamp was returned without a UTC offset, so the UI showed times shifted for users outside UTC (+05:30 in India), and an aware non-UTC value was stored as its local wall time because SQLite drops offsets. All 90 timestamp columns now use `UTCDateTime` (`app/db/types.py`): stored as UTC, always returned timezone-aware. No schema change; `alembic check` clean on SQLite and PostgreSQL. Regression tests in `test_utc_datetime.py` fail on the old code.
60. **(fixed, low)** Spatial-relationship generation silently analysed only the earliest N located records when the per-run cap was exceeded -- and a per-type `LIMIT N` hid the overflow entirely. It now fetches N+1, and the response and UI report `candidates_considered` / `candidates_truncated`.
61. **(fixed, low)** The sensor detail page kept the previous sensor's measurement type when navigating between sensors, querying a series the new sensor may not have.
62. **(fixed, medium -- availability)** With cookie sessions, `/auth/refresh` initially shared the 10/min login limit; a handful of full page loads (or tabs) signed the user out. Found by the browser route walk; fixed by `RATE_LIMIT_REFRESH` and by ending a session only on 401/403, never on 429/5xx.
63. **(fixed, low)** A failed session-restore request (signed-out visitor) left its response body unread, keeping the request open in the browser.
64. **(open, info -- model limits)** The real detector (SSD-MobileNet v1 COCO, 2017) reaches mAP@0.5 0.461 on a 200-image COCO sample, recall ~0.43 at the default threshold; it was trained on everyday photographs and is not validated on aerial, thermal, night or any operational imagery. Its output is advisory and reviewed by a person; see `docs/ml/MODEL_EVALUATION.md`.
65. **(open, info -- supply chain)** Model weights and evaluation images are third-party downloads (TensorFlow model zoo, opencv_extra, COCO). Every file is pinned by SHA-256 and verified before use; only the expected archive member is extracted. The weights are loaded by OpenCV's protobuf parser (no code execution path), but they remain an external dependency to re-verify when pins change.
66. **(fixed, medium -- availability)** `TRUST_FORWARDED_HEADERS` existed but was not wired into the rate limiter, so behind any proxy all clients shared one bucket (one visitor's failed logins throttled everyone). Fixed in rc.3 with `TRUSTED_PROXY_HOPS`; tests in `tests/test_demo_mode.py`.
67. **(open, info -- by design)** `DEMO_MODE` publishes the shared demo password on the sign-in page and exempts the demo accounts from lockout. It is for throwaway showcase data only; `scripts/demo_server.py` refuses anything but a SQLite file it deletes on every cycle. Never enable it where real data is stored.
68. **(open, low -- configuration)** With `TRUST_FORWARDED_HEADERS=true`, a `TRUSTED_PROXY_HOPS` value larger than the real number of proxies lets a client choose its rate-limit key by sending its own `X-Forwarded-For`. Set it to the number of proxies you run (Hugging Face and Render: 1).
