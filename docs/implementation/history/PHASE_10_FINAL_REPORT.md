## 6. Known limitations / unfinished
* Frontend was built and type-checked but **not click-tested in a browser**.
* Evaluation datasets are submitted inline as JSON (<= 20,000 samples); no dataset registry or file upload.
  The run form's model picker lists CV models only (any model id can be typed).
* Explanations exist for detections (metadata) and risk assessments (recorded factors), and linear models
  that declare weights. No registered model currently declares weights, so that path is covered only by
  synthetic test data. SHAP is reported unsupported. No saliency/attribution for detectors.
* Tracking evaluation: unchanged (fixture-based); no new ground-truth-based tracking metric.
* Scoring is structural (counts of contradiction/conflict/gaps/support/stated confidence); weights are
  documented defaults, not tuned or validated against outcomes.
* Review has no four-eyes rule (a reviewer may review their own assessment) and does not alter
  assessment status by design.
* Tenant isolation remains per-query filtering as in earlier phases (Phase 14 owns hardening).
* Leftover `__pycache__` files from early smoke runs may remain in `backend/app/`; they are git-ignored.
